# 星潮 Starwave · 双语实现方案

## 1. 目标

- 默认中文：`/`、`/all`、`/items/:id`、`/repos`、`/trending`……
- 英文：`/en`、`/en/all`、`/en/items/:id`、`/en/repos`、`/en/trending`……
- 英文读者看到英文 UI + 英文标题/摘要；没有英文内容时回退原文。
- 中文读者不受影响，不增加首屏成本。
- SEO：`hreflang`、英文 canonical、双语 sitemap。

## 2. 范围

### P2 必做

| 页面 | 中文 | 英文 |
|---|---|---|
| 首页 | `/` | `/en` |
| 全部动态 | `/all` | `/en/all` |
| 条目详情 | `/items/:id` | `/en/items/:id` |
| 事件页 | `/story/:publicId` | `/en/story/:publicId` |
| 日报/周报 | `/daily`、`/weekly` | `/en/daily`、`/en/weekly` |
| 主题 | `/topics`、`/topics/:slug` | `/en/topics`、`/en/topic/:slug` |
| 仓库 | `/repos`、`/repos/:owner/:name` | `/en/repos`、`/en/repos/:owner/:name` |
| 星榜 | `/trending` | `/en/trending` |
| 关于 | `/about` | `/en/about` |

### P2 不做

- 后台英文化
- 日报/周报总述、事件综述的英文翻译（英文页先做 Headlines 视图）
- 英文 RSS（可后补 `/en/feed.xml`）
- 英文 MCP/API（API 字段可带 `titleEn`，但接口说明仍中文）

## 3. UI 字典

### 3.1 文件

```text
site/locales/
  zh.ts        # 中文 UI 字符串（从现有组件里抽出）
  en.ts        # 英文
  index.ts     # Locale 类型、默认值、t() 类型
```

结构：

```ts
export const zh = {
  nav: { selected: "精选", all: "全部", hot: "热点", repos: "仓库", trending: "星榜", topics: "主题" },
  common: { readMore: "阅读原文", updated: "更新于", stars: "stars", weekDelta: "本周" },
  home: { today: "今日精选", weeklyBoard: "本周星榜", rising: "新星榜" },
  repo: { verdict: "一句话判断", tryIt: "上手", risks: "风险", related: "相关报道" },
  // ...
} as const;

export type MessageKey = keyof typeof zh;
```

`en.ts` 必须与 `zh.ts` 同结构；TypeScript 用 `satisfies typeof zh` 保证不漏键。

### 3.2 读取

```tsx
// apps/web/app/lib/i18n.tsx
const LocaleContext = createContext<"zh" | "en">("zh");
export function LocaleProvider({ locale, children }) { ... }
export function useLocale() { ... }
export function useT() {
  const locale = useLocale();
  return (key: MessageKey) => messages[locale][key] ?? messages.zh[key];
}
```

- `root.tsx` 从 `request.url` 判断 `/en` 前缀，注入 `LocaleProvider` 和 `<html lang>`。
- 服务端渲染与客户端一致；不做 hydration 后切换，避免闪烁。

### 3.3 链接

```tsx
export function LocaleLink({ to, ...props }) {
  const locale = useLocale();
  const href = locale === "en" ? (to.startsWith("/") ? `/en${to}` : to) : to;
  return <Link to={href} {...props} />;
}
```

- 只替换公开页面的 `<Link>`；后台和 API 不动。
- 英文路由内部跳转保持 `/en` 前缀；语言切换器把当前 path 去掉/加上 `/en`。

## 4. 路由

`apps/web/app/routes.ts` 增加英文路由，指向同一批 route 模块：

```ts
const en = (path: string, file: string, id?: string) => route(`en/${path}`, file, id ? { id: `en-${id}` } : {});
```

注意：

- 动态路由 id 不能和中文路由冲突，统一加 `en-` 前缀。
- loader 通过 `request.url` 判断 locale，不需要额外参数。
- 英文路由只注册 P2 范围内的页面；其余 `/en/*` 404。
- 模块页面：`modules/github/module.ts` 增加英文路径，或在模块内注册两份；推荐在 `module.ts` 里声明 `en/repos` 等。

## 5. 内容字段

### 5.1 数据库

```sql
-- 0128_publication_i18n.sql
ALTER TABLE analyses ADD COLUMN title_en text;
ALTER TABLE analyses ADD COLUMN summary_en text;

ALTER TABLE publications ADD COLUMN title_en text;
ALTER TABLE publications ADD COLUMN summary_en text;
```

- 只加可空列，不改现有数据。
- `reason_en` 暂不做（推荐理由英文后补）。
- 仓库层 `repo_editorial.verdict_en`、`use_cases_en` 已在模块迁移里预留。

### 5.2 生成

在 `industry/prompts/content-understanding.md` 的输出 JSON 里增加两个字段：

```json
{
  "titleZh": "...",
  "summaryZh": "...",
  "titleEn": "...",
  "summaryEn": "..."
}
```

- `UnderstandSchema`（`packages/backend/src/editorial/analyze.ts`）增加 `titleEn`/`summaryEn` 可选字段。
- 同一次模型调用完成，不增加请求次数；预计 token 增加 10–15%。
- 写作结果写入 `analyses.title_en`、`analyses.summary_en`。
- `packages/backend/src/publication/publish.ts` 投影时复制到 `publications.title_en`、`summary_en`。
- 精选同步、API v1、站点 API、RSS 不需要改结构；字段可选。

### 5.3 回退顺序

英文页面显示条目时：

1. `publications.title_en` / `summary_en`
2. `publications.original_title` / 原文摘要
3. `publications.title`（中文）

仓库页：

1. `repo_editorial.verdict_en`
2. `repo_editorial.verdict_zh`
3. GitHub description（原文）

### 5.4 不发英文摘要的条目

- 模型输出为空、校验失败、或内容本身是中文 → 不生成，回退。
- 英文页对无英文内容的条目加 `noindex`（避免重复内容），但仍可读。
- 条目页 `<link rel="alternate" hreflang="en">` 只在有英文内容时输出。

## 6. SEO

- `apps/web/app/lib/seo.ts` 增加 `alternates`：
  - 中文页：`hreflang="zh-CN"` + `hreflang="en"` + `x-default`
  - 英文页：同上，canonical 指向 `/en/...`
- 英文页面 `<html lang="en">`，`og:locale=en_US`。
- `sitemap.xml` 增加英文 URL；无英文内容的条目不加。
- 英文标题/描述来自 `titleEn`/`summaryEn`；没有则用原文标题 + 站点英文描述。

## 7. 工作量与风险

| 项 | 估算 |
|---|---|
| UI 字典抽取（核心公开页面） | 2–3 天 |
| 英文路由 + LocaleProvider + LocaleLink | 1 天 |
| 数据库字段 + 分析 schema + 投影 | 1 天 |
| 提示词双语输出 + 评测 | 1 天 |
| 英文页面 QA | 1 天 |
| 合计 | 5–7 天 |

风险：

- 核心页面硬编码中文多，抽取时容易漏；用 `grep -P "[\x{4e00}-\x{9fa5}]"` 扫一遍。
- 英文路由 id 冲突；统一 `en-` 前缀。
- 英文内容质量：先抽 50 条人工评，不满意就只保留 UI 英文 + 原文标题。
- 上游合并：i18n 改动集中在 `site/locales/`、`apps/web/app/lib/i18n.tsx`、`routes.ts`、`seo.ts`；记入 `FORK-NOTES.md`。
