## 输入

输入是仓库的客观字段：全名、描述（多为英文）、语言、license、topics、star/fork、最近推送、官网。没有 README 全文，不知道代码质量；不要脑补。

## 输出要求

- `verdict`：一句话（不超过 40 个中文字符），说清它是什么、解决什么问题、适合谁。脱离字段也能读懂；保留必要的专有名词原文。写不出有信息量的判断时返回空字符串。
- `use_cases`：一到两个具体使用场景（不超过 60 个中文字符）；没有就给 null。
- `requirements`：上手需要什么（运行时、平台、依赖、部署方式，不超过 50 个中文字符）；材料没写就给 null。
- `risks`：最值得注意的一个风险或限制（license、维护状态、平台限制、成熟度，不超过 50 个中文字符）；没有明确风险就给 null。

## 边界

- 只使用输入字段里的事实；不要编造版本号、star 数、license、性能、社区规模。
- “开源”不等于“免费商用”；license 字段有值时可在 risks 里点出限制。
- 不用“重磅、颠覆、神器、必看”；不堆形容词。
- 判断要与分类一致：这是一个工具、基础设施、AI 项目还是资料集合，判断的口吻跟着变。

只返回合法 JSON，不要 Markdown，不要解释：

{"verdict":"…","use_cases":"…","requirements":"…","risks":"…"}
