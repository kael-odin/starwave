SAME_OCCURRENCE（同一次发生）：同一个主体在同一时间对同一个具体对象做的同一件事。跨语言转述、不同媒体的侧重、细节多寡、官方发布博客/Release Notes 不改变身份。

开源场景的具体口径：
- 同一个仓库的同一个 release / tag / 版本号，算同一次发生；同一版本的多个安装包、镜像、平台支持、发布说明细节，也算同一次发生。
- 同一个安全公告（同一 CVE / GHSA / 同一受影响版本范围）算同一次发生；后续补丁、修复版本、受影响范围扩大，按 SAME_STORY。
- 同一次开源动作（同一个仓库从闭源转开源、同一批代码/权重/模型开放）算同一次发生；后续补文档、加 license、上架包管理器，按 SAME_STORY。
- 同一组织的同一笔融资/收购/基金会加入算同一次发生；同一组织同一天的两个不同项目发布，是两件事。
- 同一项目在同一版本周期内发布的多个功能，如果属于同一次发布说明，算同一次发生；不同版本、不同日期的发布分别判断。
- 同一仓库的 issue 讨论、PR 合并、文档更新，只有构成可对外描述的版本/功能/安全变化时才作为发生；日常提交不构成新闻事件。

SAME_STORY（同一事件的不同进展）：不是同一次发生，但围绕同一个具体发生有直接的先后关系：
- 预告/传闻与正式发布；发布与之后在包管理器/应用商店上架、接入、限免。
- 发布与针对它的评测、实测、基准、上手体验、迁移指南、解读。
- 安全公告与后续补丁、修复版本、受影响范围扩大、官方调查。
- 开源动作与后续 license 变更、治理调整、基金会加入。
- 同一仓库不同版本之间的连续演进，只有在后一版直接回应前一版的问题/变化时才算同一事件；两个独立的功能版本不算。

UNRELATED（不同的事）：
- 不同仓库、不同项目的两次发布，即使同一组织、同一天、同一语言或同一话题。
- 同一话题的不同项目、不同观点、不同事故；只是提到同一项目或组织。
- 关于某项目的教程、用法分享、个人观点、营销帖，除非明确针对候选那一次具体发生（评测它、回应它、上架它），否则是 UNRELATED。
- 同一组织同一天的两件不同事；同一语言生态的两个不同项目。

ROUNDUP：其中一方汇集多个独立发生，把对方的事件作为多个条目之一；包括多项目盘点、日报、周报、大会回顾、多个独立项目的总览。综合稿与其中某个单事件报道不能是 SAME_OCCURRENCE 或 SAME_STORY；它同时提到两个独立事件也不代表两个事件可以合并。只是用其他事件作背景或对比论据，仍按核心发生判断，不自动算综合稿。
